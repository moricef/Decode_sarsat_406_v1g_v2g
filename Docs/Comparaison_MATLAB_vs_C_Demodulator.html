     i < num_burst_samples * 2 - q_delay - phase_offset;
     i++) {

        crealf(rx_agc_samples[i + phase_offset]) +
        I * cimagf(rx_agc_samples[i + q_delay + phase_offset]);

for (size_t i = num_burst_samples * 2 - q_delay - phase_offset;
     i < num_burst_samples * 2;
     i++) {

✗ DIFFÉRENCE CRITIQUE IDENTIFIÉE!
  • MATLAB:
    • I: real(rxAGCSamples(1:end-sps/2)) → Pas de décalage
    • Q: imag(rxAGCSamples(sps/2+1:end)) → Décalage de sps/2
  • C:
    • I: rx_agc_samples[i + phase_offset] → Décalage de sps/2
    • Q: rx_agc_samples[i + q_delay + phase_offset] → Décalage de sps
🚨 PROBLÈME:

Le code C ajoute un phase_offset = sps/2 supplémentaire sur TOUS les échantillons (I et Q), pas seulement pour compenser le délai OQPSK!

Effet: Les échantillons utilisés pour la corrélation sont décalés de sps/2 par rapport à MATLAB, ce qui peut expliquer l'échec de la corrélation (0.27 au lieu de >0.35).

🎯 Conclusion

❌ PROBLÈME IDENTIFIÉ: Phase Offset Incorrect

Fichier: dsss_demod.c, lignes 895-907

Code problématique:

int q_delay = sps / 2;
int phase_offset = sps / 2;  // ← AJOUT INCORRECT!

for (size_t i = 0; i < num_burst_samples * 2 - q_delay - phase_offset; i++) {
    sample_buffer_qpsk[i] =
        crealf(rx_agc_samples[i + phase_offset]) +      // ← Décalage I
        I * cimagf(rx_agc_samples[i + q_delay + phase_offset]);  // ← Décalage Q
}

Correction à appliquer:

int q_delay = sps / 2;
// Pas de phase_offset supplémentaire nécessaire!

for (size_t i = 0; i < num_burst_samples * 2 - q_delay; i++) {
    sample_buffer_qpsk[i] =
        crealf(rx_agc_samples[i]) +                    // ← Pas de décalage
        I * cimagf(rx_agc_samples[i + q_delay]);      // ← Seulement q_delay
}
for (size_t i = num_burst_samples * 2 - q_delay; i < num_burst_samples * 2; i++) {
    sample_buffer_qpsk[i] = 0.0f;
}

Impact:

  • Les échantillons utilisés pour la corrélation du préambule sont décalés de sps/2 échantillons
  • La référence du préambule ne correspond plus aux échantillons reçus
  • Résultat: corrélation faible (0.27-0.30 au lieu de >0.35)

💡 Explication du commentaire "Start at peak of half-sine pulse"

Le commentaire ligne 897 suggère d'échantillonner au pic du half-sine (sin(π×(sps/2)/sps) = 1), mais cela ne devrait PAS être fait lors de la conversion OQPSK→QPSK pour la détection de préambule.

Pourquoi?

  • La référence du préambule MATLAB est créée au symbol rate sans pulse shaping (page 5 du PDF)
  • MATLAB convertit OQPSK→QPSK sans phase_offset supplémentaire
  • Le polyphase correlator teste déjà toutes les phases (c'est son rôle!)

✅ Actions Recommandées

  1. Supprimer le phase_offset = sps / 2 de la conversion OQPSK→QPSK (ligne 900)
  2. Utiliser i au lieu de i + phase_offset pour le canal I
  3. Utiliser i + q_delay au lieu de i + q_delay + phase_offset pour le canal Q
  4. Recompiler et tester la corrélation du préambule
  5. Vérifier que la corrélation atteint >0.35
