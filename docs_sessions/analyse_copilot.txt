### Résumé rapide de compatibilité

- Incompatible par défaut : le générateur C produit un signal à 2.5 MHz (≈65.104 samples/chip) tandis que l’exemple MATLAB/receiver que vous avez montré utilise fs ≈ 307.2 kHz (sps = 8 → 8 samples/symbole → 8 samples/chip dans ce contexte).  
- Plusieurs composants clés sont pourtant compatibles ou cohérents entre eux : spreadingFactor = 256 chips/bit, OQPSK (Q retardée de Tc/2), préambule 50 bits et payload 250 bits, convention d’inversion PRN (bit=1 → inversion), et usage d’un filtre RRC côté émetteur (α = 0.5).  

---

### Paramètres du générateur (extraits du code)
- **Sample rate (OQPSK_SAMPLE_RATE)** : 2.5 MHz (annoncé dans l’entête et imprimé)  
- **Chip rate (OQPSK_CHIP_RATE)** : 38.4 kchips/s  
- **Samples per chip (OQPSK_SAMPLES_PER_CHIP)** : ≈ 65.104 (2.5e6 / 38.4e3) — code gère accumulation fractionnaire et interpolation linéaire entre chips  
- **Spreading factor / chips par bit** : 256 (PRN_CHIPS_PER_BIT = 256 → 150 bits × 256 = 38 400 chips par voie I/Q)  
- **Trame** : préambule 50 bits (tous 0) + 250 data bits → 300 bits transmis → séparation impair/paire → 150 bits I / 150 bits Q  
- **Modulation** : OQPSK (Q retardée de Tc/2), interpolation linéaire entre chips, PRN inversion pour bit=1  
- **Mise en forme** : RRC pulse shaping appliqué après génération (α = 0.5 d’après entête)  
- **Durée annoncée** : ~1000 ms (cohérent : 300 bits à 300 bps → 1 s)

---

### Ce que le récepteur MATLAB attend (rappel de l’analyse antérieure)
- **fs (récepteur)** dans l’exemple précédent : 307 200 Hz (déduit de chipRate 38.4 kHz × sps = 8)  
- **SPS** : 8 dans l’exemple MATLAB (sps = 2 * settings.oversampling = 8)  
- **num_burst_samples** calculé précédemment : 307 200 échantillons pour un burst (150 symboles × 256 chips × 8 sps = 307200)  
- **Spreading factor** : 256 (même valeur)  
- **Structure trame/preambule/PRN inversion** : même convention T.018 (préambule 50 bits à 0, inversion PRN pour 1)

---

### Liste précise des incompatibilités et risques
1. Échantillonnage (fréquence)  
   - Générateur : 2.5 MHz. Récepteur MATLAB : 307.2 kHz. Résultat : différent nombre d’échantillons par chip/symbole → corrélation direc te, synchronisation et buffers incompatibles sans rééchantillonnage.

2. Samples per chip (granularité temporelle)  
   - Générateur ≈ 65.104 s/chip (non entier). Récepteur supposant 8 sps (entier). L’algorithme de détection basé sur corrélations sur des échantillons/tableaux fixes échouera si la résolution temporelle n’est pas adaptée.

3. Filtrage et mise en forme (RRC)  
   - Générateur applique RRC α=0.5. Le récepteur doit utiliser le même filtre ou connaître la réponse pour la corrélation et la synchronisation ; s’il attend des pulses « carrés » ou une autre α, les corrélations et l’égalisation seront dégradées.

4. Interpolation / timing OQPSK  
   - Générateur fait interpolation linéaire et gère le retard Q Tc/2 au niveau échantillon non entier ; le récepteur doit pouvoir détecter/synchroniser ce décalage sur sa grille d’échantillonnage.

5. Format et amplitude  
   - Générateur sort des floats I/Q interleaved. Le récepteur MATLAB doit accepter ce format et la normalisation d’amplitude (le vérificateur attend puissance ≈1). Si le récepteur suppose une échelle différente ou un format int16/complex64, conversion requise.

6. Durée / buffers  
   - Générateur génère ~2.5M échantillons (38400 chips × 65.1 ≈ 2 499 840 samples) → mémoire et taille de buffer différente de l’exemple MATLAB qui traitait ~307k échantillons par burst.

---

### Éléments compatibles (points positifs)
- Spreading factor = 256 chips/bit (même conception DSSS)  
- PRN inversion convention identique (bit=1 → inversion)  
- Trame T.018 : préambule 50 bits et séparation I/Q impair/paire → structure logique compatible  
- Modulation OQPSK avec Q retardée Tc/2 → même type de modulation attendu par le récepteur  
- Existence d’un RRC côté TX, le récepteur MATLAB peut être adapté pour utiliser la même RRC (ou la compenser)

---

### Actions recommandées pour rendre les deux compatibles
1. Option simple (préférée) : rééchantillonnage  
   - Ré-échantillonner le flux TX de 2.5 MHz → 307.2 kHz avant d’alimenter le récepteur MATLAB (facteur ≈ 2.5e6 / 307200 ≈ 8.1389). Faire un décimateur anti‑aliasing de bonne qualité (filtre) ou rééchantillonner dans le domaine numérique pour obtenir exactement 8 samples/chip si le récepteur l’exige.

2. Adapter le récepteur MATLAB au taux du TX  
   - Re-calculer et remplacer fs, sps, num_burst_samples dans le receiver pour correspondre à OQPSK_SAMPLE_RATE et OQPSK_SAMPLES_PER_CHIP (≈65.104). Cela exige d’ajuster corrélateurs, seuils, taille de buffer et potentiellement la logique de synchronisation pour une non‑integer samples/chip si le code MATLAB suppose des entiers.

3. Aligner la mise en forme RRC  
   - Vérifier que le récepteur applique la même RRC (α = 0.5, mêmes délais et longueur) ou, si le récepteur suppose un pulse différent, supprimer/adapter le filtrage côté TX ou compenser côté RX (filtre inverse).

4. Vérifier la convention PRN & bit ordering  
   - Confirmer l’ordre des bits (endianness) et la séparation I/Q attendue par le récepteur (le générateur prend bits impairs → I, pairs → Q). Assurer que le récepteur utilise la même convention.

5. Format de fichier / échelle  
   - Si vous passez les fichiers .iq au récepteur, vérifier format (float32 interleaved I,Q), taille, et normalisation d’amplitude. Convertir en le format attendu par le receiver (par ex. complex double, int16) si nécessaire.

6. Tests pratiques à effectuer  
   - Générer un burst, rééchantillonner vers fs MATLAB et exécuter la chaîne RX en mode « idéal » (pas d’impairements) pour valider détection de préambule et décodage.  
   - Vérifier corrélation PRN au récepteur : pic attendu à bonne position et rapport signal/bruit raisonnable.  
   - Tester variantes de Doppler/offset si le RX implémente compensation.

---

### Verdict succinct
Le générateur C implémente correctement la norme T.018 (préambule 50 bits, 250 data bits, DSSS 256 chips/bit, OQPSK Tc/2, PRN inversion, RRC α=0.5) et donc est conceptuellement compatible avec le récepteur MATLAB sur le plan protocolaire. En revanche, il n’est pas directement compatible en pratique à cause d’un désaccord majeur sur la fréquence d’échantillonnage / nombre d’échantillons par chip. Pour interopérabilité il faut soit rééchantillonner le signal TX vers la fréquence attendue par le récepteur, soit adapter les paramètres et les algorithmes du récepteur pour accepter le flux à 2.5 MHz et l’interpolation non entière.
