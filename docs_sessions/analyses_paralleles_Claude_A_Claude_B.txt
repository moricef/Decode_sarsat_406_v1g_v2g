  4.3 Despreading - BUG TROUVÉ!

  Notre code (dsss_demod.c:814-822):
  // Step 5 - DSSS Despreading
  int8_t *rx_ci = malloc(DSSS_PACKET_CHIPS);  // uint8_t 0/1 de qpsk_demod
  int8_t *rx_cq = malloc(DSSS_PACKET_CHIPS);
  ...
  int8_t *ibdn = malloc(DSSS_PACKET_CHIPS);
  int8_t *qbdn = malloc(DSSS_PACKET_CHIPS);

  for (size_t i = 0; i < DSSS_PACKET_CHIPS; i++) {
      ibdn[i] = rx_ci[i] ^ prn_i[i];  // ❌ BUG ICI!
      qbdn[i] = rx_cq[i] ^ prn_q[i];
  }

  Problème identifié:
  - rx_ci[i]: uint8_t avec valeurs 0 ou 1
  - prn_i[i]: int8_t avec valeurs -1 (+0xFF) ou +1

  Exemple du bug:
  rx_ci[0] = 1 (uint8_t)
  prn_i[0] = -1 (int8_t) = 0xFF en représentation binaire
  XOR: 0x01 ^ 0xFF = 0xFE = 254 ❌

  Attendu (MATLAB):
  rx.Ci[0] = 1 (logical)
  PRN_I[0] = 1 (logical)  
  XOR: 1 ^ 1 = 0 ✅

  7. ROOT CAUSE

  Le bug est dans dsss_demod.c:820-821:

  ibdn[i] = rx_ci[i] ^ prn_i[i];  // XOR entre uint8_t (0/1) et int8_t (-1/+1)

  Pourquoi ça ne marche pas:
  - En C, XOR bit-à-bit: 1 ^ (-1) = 0x01 ^ 0xFF = 0xFE (254)
  - Attendu (logique): 1 ^ 1 = 0

  Solution requise:
  Soit convertir prn_i/prn_q de (-1,+1) vers (0,1) avant XOR,
  Soit utiliser une comparaison logique au lieu de XOR.
